# Few open models beat Flash-Next on ryzen

No open-weight model available on 2026-11-21 clearly outperforms Qwen3.8-Flash-Next (UD-IQ4_XS on Strata 0.2.13) for multi-hour, 100K–250K-context agentic Rust work on ryzen's single R9700 and roughly 85 GiB of RAM. The models with clearly better agentic scores (DeepSeek V4.1-Flash-1017, MiniMax-M3.1-Flash, MiMo-V2.6-Flash, GLM-5.3-Flash) are 300–760B-parameter MoEs. On this box they either do not fit at a sane quant or decode at roughly 6–26 tok/s against the baseline's 80–95. Four options plausibly beat the baseline on a quality dimension, in this order. **First, the same model at a better quant (UD-Q4_K_XL)**, which halves KL divergence from Q8 at a small speed cost. **Second, the pruned 2-bit DeepSeek V4.1-Flash-1017 "ISTA-DAS Coder"**, which has the strongest parent model, but runs 3.5–4x slower, only on Strata ≤0.2.13, and needs an engine the current image does not bundle. **Third, GLM-5.3-Flash at 2-bit**, which has the best independent Terminal-Bench numbers of anything that physically fits, but is borderline on memory, heavily quantized and needs a llama.cpp fork. **Fourth, Nanbeige4.3-33B**, which beats the baseline on one independent benchmark but cannot hold 250K context. The previously evaluated Tencent Hy4-Flash and Inkling 2 Mini rank below the baseline on independent boards as well as on the earlier reasoning, and Inkling 2 Small does not fit. Every comparison rests on vendor numbers from mismatched harnesses. The baseline has no independent SWE-style coding score, and no Rust-specific evidence exists for any candidate. So the decisive step is a small private Rust A/B on this box, not a model swap.

## The hardware rewards Strata's one model and punishes everything else

The real competition is not the model but the runtime. Strata gets about 90 tok/s from a 125–180B MoE on a 32 GB card by keeping a hot-expert cache in VRAM, computing cache misses on the CPU with AVX-512, and adding MTP speculative decoding worth **1.6–1.8x** ([Strata HOW_IT_WORKS](https://github.com/Niko1221/Strata/blob/HEAD/docs/HOW_IT_WORKS.md)). A community R9700 run measured **101.9 tok/s decode at 1K and 87.6 at 128K**, with prompt reading at 630–770 tok/s on an IQ3_S pack ([Strata R9700 bench](https://raw.githubusercontent.com/Niko1221/Strata/HEAD/docs/bench-results/2026-10-08-community-r9700-linux/README.md)). That matches ryzen's own 80–95 tok/s. Current Strata supports only Qwen-family models ([Strata MODELS.md](https://github.com/Niko1221/Strata/blob/main/docs/MODELS.md)). It removed DeepSeek in 0.2.14, so 0.2.13 is the last release that runs it ([DEEPSEEK41.md](https://github.com/Niko1221/Strata/blob/main/docs/DEEPSEEK41.md)). Any other architecture falls back to llama.cpp with static `--n-cpu-moe` expert offload. Upstream llama.cpp has no GPU hot-expert cache ([llama.cpp #20757](https://github.com/ggml-org/llama.cpp/issues/20757)). On ryzen that path measured only 12.5–29 tok/s decode and 286–449 tok/s prompt for the very same baseline model.

Community data puts llama.cpp offload of 100–300B MoEs on 24–32 GB cards with dual-channel DDR5 at **roughly 10–30 tok/s decode and 65–450 tok/s prefill**. DeepSeek-V4-Flash (284B/13B active) managed about **15 tok/s tg and 150 tok/s pp** on a 3090 Ti with DDR5-6400 ([HF antirez discussion #16](https://huggingface.co/antirez/deepseek-v4-gguf/discussions/16)). The rule of thumb is decode ≈ 0.4–0.6 × RAM bandwidth ÷ active expert bytes per token ([GPUwerk](https://gpuwerk.com/blog/moe-cpu-offload-llama-cpp/)). That predicts about 15–30 tok/s for 5B-active, 7–15 for 13B-active and under 10 for 20B-plus active on this box. The vLLM and SGLang alternatives are not viable here. vLLM's CPU offload streams every offloaded weight on each forward pass instead of caching hot experts ([vLLM forum](https://discuss.vllm.ai/t/enable-expert-offloading/1884)). KTransformers' ROCm path is beta and has no RDNA4 validation ([KTransformers ROCm](https://kvcache-ai.github.io/ktransformers/en/ROCm.html)).

Long context compounds the gap. Hybrid linear-attention models (the baseline's DeltaNet, Ling's KDA, GLM-5.3-Flash's sparse+linear mix) and compressed-attention models (DeepSeek CSA) keep KV small enough for 250K on 32 GB. Full-GQA dense models do not. Nanbeige4.3-33B, for example, needs about 208 KiB/token, or roughly **56 GB of fp16 KV at 256K** ([Nanbeige config.json](https://huggingface.co/Nanbeige/Nanbeige4.3-33B/raw/main/config.json)). Two things limit any move away from the baseline: speed for multi-hour sessions, and prompt-reading rate for 100K–250K contexts after a cache miss. A model that is 10% smarter but 4x slower turns a 2-hour agent run into an 8-hour one. At 0.4K tok/s it also re-reads a 200K context in over 8 minutes, against about 2 minutes on the baseline.

## The baseline is strong on paper but thinly verified

Qwen3.8-Flash-Next's vendor coding numbers, as relayed in this conversation from the Qwen release ([Qwen blog](https://qwen.ai/blog?id=qwen3.8-flash-next)), are **SWE-bench Pro 62.5 (Claude Code harness), SWE-bench Multilingual 81.0 (mini-SWE-agent), DeepSWE v1.1 58.7 and Toolathlon 73.5**. None of these has been reproduced independently. The model is absent from SWE-rebench, whose newest window ends 2026-07-01, before its release ([SWE-rebench](https://swe-rebench.com/leaderboard)). It is also absent from every Vals.ai board ([Vals Index](https://www.vals.ai/benchmarks/vals_index)) and from tbench.ai's Terminal-Bench 4.1 ([tbench.ai](https://www.tbench.ai/leaderboard)). The only third-party figures come from Artificial Analysis: **Intelligence Index 29** (v5.0.1, #10 of 33 open models in its class), **Terminal-Bench 4.0 25.3%** and AutomationBench 55.9% ([AA model page](https://artificialanalysis.ai/models/qwen3-8-flash-next); [AA comparison](https://artificialanalysis.ai/models/comparisons/nanbeige4-3-33b-vs-qwen3-8-flash-next)). AA also flags it as slow and verbose: **34.9 minutes per index task** against a peer median of 14.7, and 156M output tokens per run against a median of 104M. In multi-hour sessions, verbosity costs real time even at 90 tok/s. Even its size is disputed: AA lists 180B/6B active, while Qwen describes 125B plus 51B of n-gram embeddings ([Qwen on X](https://x.com/Alibaba_Qwen/status/2092591393424515114)). The second description reconciles the two.

Three comparability traps run through every number below. **Harnesses differ.** DeepSeek V4.1-Flash scores 74.2 on DeepSWE v1.1 under mini-SWE but **65.5 under OpenCode**, from the same vendor and weights ([DeepSeek card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)). **Benchmark versions differ.** AA runs Terminal-Bench 4.0, Vals runs 4.0 with mini-swe-agent, and tbench.ai shows 4.1 with mixed agents, so DeepSeek 1017 scores 31.8% on Vals and 38.5% on tbench ([Vals TB4](https://www.vals.ai/benchmarks/terminal-bench-4)). **Benchmarks churn.** SWE-bench Verified is archived as saturated ([Vals SWE-bench](https://www.vals.ai/benchmarks/swebench)), and SWE-Bench Pro V2 repaired or retired 480 of 731 original Pro tasks, so a "SWE-bench Pro 62.5" may not be comparable with newer Pro scores ([arXiv 2610.24206](https://arxiv.org/abs/2610.24206)). Some boards also look like they measure tool-protocol failure rather than capability. MiniMax M3 scores 75% on Vals SWE-bench Verified but 7.6% on tbench's TB4.1 ([tbench.ai](https://www.tbench.ai/leaderboard)). The only like-for-like independent agentic comparison available is **AA's Terminal-Bench 4.0**: GLM-5.3-Flash 32.8, Nanbeige4.3-33B 29.8, Qwen3.8-Flash-Next 25.3, Mistral Large 4 24.7, Qwen3.8-27B 5.6 ([GPUwerk ranking of AA data](https://gpuwerk.com/blog/best-open-weight-coding-models/)).

On Rust, the evidence is a void. Modal's July 2026 guide states that no consistent Rust-only benchmark exists across models and declines to rank any of them ([Modal](https://modal.com/resources/best-open-source-models-rust-coding-agents)). The best Rust data is older academic work. Rust-SWE-bench's 500 tasks topped out at **21.2% resolved for OpenHands + Claude Sonnet 3.7**. Compile failures were dominated by path/scope resolution (43.7%) and trait/type violations (32.6%), and 44.5% of failures came from not reproducing the issue, often because of Cargo configuration ([arXiv 2602.22764](https://arxiv.org/html/2602.22764v1)). The baseline's SWE-bench Multilingual 81.0 is the only Rust-touching number for any candidate, and it is vendor-reported.

| 4 | **Nanbeige4.3-33B** dense, AD-Q4_K_M, fully in VRAM | AA TB4.0 29.8 vs 25.3 (independent); AA Index 20 vs 29; DeepSWE 65.5 (vendor, mini-swe-agent) | Estimated 22–26 tok/s, no MTP | **~100K at q8 KV, ~180–200K at q4 KV; 256K impossible** | Looping and failed tasks in the only hands-on review; quant-sensitive |

**The higher-bit quant of the current model is the safest upgrade, even though it is the same model.** Strata's own KL table measures UD-IQ4_XS at mean KL 0.101 and 88.9% top-token agreement with Q8_0. UD-Q4_K_XL measures **0.056 and 93.1%**, and its p99 KL falls from 1.60 to 0.83 ([Strata QUANTS.md](https://github.com/Niko1221/Strata/blob/main/docs/QUANTS.md)). That tail matters for long tool chains, where one bad token can derail a call. On older engines the R9700 ran UD-Q4_K_XL at 87 tok/s code decode against 95 for IQ3_S, with 32K prompts at 1,110–1,320 tok/s ([Strata MODELS.md](https://github.com/Niko1221/Strata/blob/main/docs/MODELS.md)). That suggests a roughly 5–15% speed cost. It needs about 88 GB of RAM for all experts, and Strata only keeps everything resident with 16 GB to spare, so a slice will stream from NVMe. It runs on the engine already deployed, so it needs no upgrade to 0.2.14+ and avoids the long-prompt stall the brief cites in [Strata #6420](https://github.com/Niko1221/Strata/issues/6420). It will not add capability the model lacks. It removes quantization damage, which is the one known, measurable deficit of the current setup.

**DeepSeek V4.1-Flash-1017 is the only fitting option whose parent model is clearly a tier above the baseline on independent boards.** On Vals it leads every open "Flash" model: Index **61.26%**, Vibe Code **87.73%**, TB4.0 31.82% ([Vals Index](https://www.vals.ai/benchmarks/vals_index); [Vals Vibe Code](https://www.vals.ai/benchmarks/vibe-code)). AA gives it 33 against the baseline's 29 ([AA open-source](https://artificialanalysis.ai/models/open-source)). The vendor's DeepSWE v1.1 gap is 77.0 against 58.7 ([1017 card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017)), which narrows to about 7 points under OpenCode. The model itself is 763B including a 196B Engram table, so only the pruned **ISTA-DAS Coder** (72 GB backbone plus a 110.6 GB Engram file that stays on SSD) fits ryzen's RAM and VRAM. Pruning plus 2-bit costs it **KL 0.397, top-1 76.4%, perplexity 4.645 vs 3.140**, though it still passed 54/61 on Strata's suite ([Strata v0.2.10](https://github.com/Niko1221/Strata/releases/tag/v0.2.10)). Its vendor SWE-bench Verified is 77.0, against 82.8 for the BF16 Qwen base at different reasoning efforts ([ISTA DS Coder card](https://huggingface.co/ISTA-DASLab/DeepSeek-V4.1-Flash-1017-GSQ-RCO-Coder-GGUF); [ISTA Qwen Coder card](https://huggingface.co/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF)). So it is unproven whether the pruned Coder beats the 4-bit baseline at all. Its costs are concrete: 22.8–25.6 tok/s decode on one R9700, 366 s from launch to ready, and 32K prompts at 382–444 tok/s ([Strata v0.2.7](https://github.com/Niko1221/Strata/releases/tag/v0.2.7); [v0.2.13](https://github.com/Niko1221/Strata/releases/tag/v0.2.13)). One in five runs inserted a "DSML" marker into tool arguments while experts streamed from SSD ([v0.2.10](https://github.com/Niko1221/Strata/releases/tag/v0.2.10)). A read-only `kubectl exec` on the strata-ryzen pod showed only `components/engine/0.1.59-linux-x86_64-hip-rx9070`, with **no `strata-dsv41` engine**, so running it means fetching that component from the 0.2.13 release. Its return to current Strata is promised but undated ([issue #6072](https://github.com/Niko1221/Strata/issues/6072)). It belongs in a quality-ceiling experiment, not in daily use.

**GLM-5.3-Flash has the best independent agentic numbers of anything that physically fits, but only at a quant its own quantizer marks as degraded.** It scores 32.8 on AA's TB4.0, the same harness that gives the baseline 25.3 ([GPUwerk](https://gpuwerk.com/blog/best-open-weight-coding-models/)). It also scores 37.37% on Vals TB4, 37.0% on tbench TB4.1 and 92.0% on Vals' archived SWE-bench Verified, but collapses to **30.76% on Vibe Code** ([Vals Vibe Code](https://www.vals.ai/benchmarks/vibe-code)), a pattern that looks like a long-build or harness failure. Its AA Index is 28, a point below the baseline's 29. At 320B/18B active, the only quant that fits is **UD-Q2_K_XL at 108.7 GB, with KLD 0.380 and 78.3% top-1**, and Unsloth recommends 128–150 GB for 3-bit. Support depends on llama.cpp PR #27754 or an Unsloth fork branch ([Unsloth GLM-5.3-Flash](https://unsloth.ai/docs/models/glm-5.3-flash)). With 18B active, llama.cpp offload on dual-channel DDR5 should land in single digits to low teens of tok/s (an inference from the bandwidth model). Unsloth's own guidance puts Q2_K_XL right at the floor for reliable tool calling ([Unsloth Dynamic 3.0](https://unsloth.ai/docs/basics/dynamic-3.0-ggufs)). It is a legitimate candidate for a short eval, not for multi-hour sessions.

**Nanbeige4.3-33B is the only fully in-VRAM model that independently beats the baseline on anything, and it fails the context requirement.** AA measures **TB4.0 29.8% vs 25.3%**, but Intelligence Index 20 vs 29 and AutomationBench 53.1% vs 55.9% ([AA comparison](https://artificialanalysis.ai/models/comparisons/nanbeige4-3-33b-vs-qwen3-8-flash-next)). It also uses 44% more tokens than Qwen3.8-27B for the same AA score ([AA article](https://artificialanalysis.ai/articles/nanbeige-has-released-nanbeige4-3-33b-scoring-20-on-the-intelligence-index)). Its vendor DeepSWE of 65.5 came from mini-swe-agent v2.4.6 and cannot be compared with Qwen's 58.7 ([HF card](https://huggingface.co/Nanbeige/Nanbeige4.3-33B)). It is a full-GQA dense model with no MTP. At AD-Q4_K_M (21.2 GB) it leaves roughly 11–13 GB for KV, which works out to about 100K tokens at q8 and 180–200K at q4, on a model its quantizer calls "unusually sensitive to quantization" ([AtomicChat GGUF](https://huggingface.co/AtomicChat/Nanbeige4.3-33B-GGUF)). The only hands-on agentic review recorded more than an hour of looping on a debugging task without finding the bug ([MindStudio](https://www.mindstudio.ai/blog/nanbeige-4-3-33b-benchmark-test)).

## Test before switching: a small private Rust A/B

Because no external number settles the question, the evidence-producing move is a private eval on ryzen itself. Build **20–40 tasks from your own Rust repositories**. Good sources are commits that fixed a real bug or added a feature with tests: revert the fix, keep the tests hidden, and give the agent the issue text. Include several tasks that start from a preloaded 150K–220K context, because that regime is where models and runtimes diverge. Grade mechanically with `cargo check`, `cargo clippy -D warnings` and the hidden `cargo test`, and record time to green, total output tokens, tool-call parse errors, loop or abort events, and cache-reuse rate. Run each task **at least 3 times per model**. Strata's expert cache is nondeterministic even at temperature 0, and disabling it costs 58% of decode ([v0.2.10](https://github.com/Niko1221/Strata/releases/tag/v0.2.10)). Use your real agent harness: harness choice moved DeepSeek's DeepSWE by nearly 9 points, and Rust-SWE-bench found that reproduction and Cargo setup failures dominate.

Order the A/B by cost. **First**, run UD-IQ4_XS against UD-Q4_K_XL on the existing Strata 0.2.13 pod. This is a model-path swap with no engine change, and it tells you whether quantization error is costing you anything. **Second**, add Swift 1.5 if time-to-green is dominated by thinking length, given AA's verbosity flag. **Third**, as a quality ceiling, run the DeepSeek ISTA-DAS Coder in a separate pod pinned to 0.2.13 with the `strata-dsv41` 0.1.59 component fetched in, using a subset of tasks. If it solves clearly more tasks despite the 3.5–4x wall-clock penalty, that argues for overnight batch runs or for waiting until DeepSeek returns to current Strata. **Optionally**, run GLM-5.3-Flash UD-Q2_K_XL and Nanbeige4.3-33B (contexts ≤128K only) on llama.cpp ROCm on a handful of tasks, to see whether their Terminal-Bench edge carries over to Rust. Do not upgrade production Strata past 0.2.13 for this work until [#6420](https://github.com/Niko1221/Strata/issues/6420)'s long-prompt GPU stalls on R9700 with this exact model are resolved. The upgrade would also drop DeepSeek support.

## Conclusion

On ryzen, the decision is set more by memory bandwidth than by leaderboards. Strata's expert cache gives a roughly 4x speed advantage to one model family, and every model with clearly better agentic scores is 2.5–6x larger than the baseline. In practice, "better" means either the same model with less quantization damage or a far slower model with a higher ceiling. The most likely real-world gain therefore comes from two cheap moves: a 4-bit K-quant on the engine already running, and an eval harness that measures the Rust-specific failure modes (paths, traits, Cargo) that matter here. It is unlikely to come from a new model in the next few weeks.

Two developments would change this picture. DeepSeek's return to a current Strata release with multi-card-class caching would make the strongest "Flash" parent a realistic candidate. A llama.cpp hot-expert cache, or Strata support for GLM/MiniMax architectures, would bring the 300–430B Flash tier into range at usable speeds.
